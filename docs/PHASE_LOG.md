## Phase 1 — Data acquisition & validation (2026-10-14)

**Goal:** get the 9 raw CSVs, load them with correct dtypes, validate with pandera, and write a
code-generated data-quality report.

**Acceptance (BUILD_PLAN):** `make data` downloads 9 CSVs; validation runs; data-quality report
exists and its numbers come from code.

**Built**
- `src/ontime/data/download.py` - Kaggle API download; skips if all 9 files present; raises a
  clear message with credential instructions if Kaggle auth is missing.
- `src/ontime/data/load.py` - loads any/all tables; zip prefixes as strings, timestamps parsed.
- `src/ontime/data/schemas.py` - pandera schemas for all 9 tables (types, key uniqueness,
  allowed categories, non-negative ranges).
- `src/ontime/data/quality.py` - generates `reports/data_quality.md` (row counts, schema status,
  null %, duplicate keys, inconsistent values, geolocation outliers/coverage).
- `pipeline.py` - `data` stage wired up (`make data`).
- `tests/test_data_quality.py` - 5 tests on tiny fixtures.
- Added dependency `tabulate` (needed by `DataFrame.to_markdown`; tiny, not heavy).

**Dataset location note:** user downloaded into `data/raw/archive/`; files were moved up to
`data/raw/` to match `configs/config.yaml`.

**Results (all from `reports/data_quality.md`, generated by code)**
- 9/9 schemas pass. orders 99,441 rows; order_items 112,650; geolocation 1,000,163.
- orders nulls: approved_at 0.16%, delivered_carrier 1.79%, delivered_customer 2.98%.
- Duplicate keys: none, except `reviews.review_id` (814 duplicate rows).
- Inconsistencies: 61 orders delivered before approval; 8 'delivered' orders with no delivery
  date; 6 non-delivered orders that have one.
- Geolocation: 42 points outside Brazil box; 261,831 exact duplicate rows; 278 customer rows and
  7 seller rows whose zip prefix has no geolocation entry (will need state-centroid fallback).

**Open items carried forward**
- Reviews: duplicate review_id and possibly several reviews per order - handle in Phase 3.
- The 8 + 61 + 6 inconsistent orders must be handled in Phase 2 population filters.

**Verification:** `pytest` 8 passed; ruff check + format clean.
